# Script Skill: iot_car

## 1. 系統架構與資料來源

本 Skill 不直接連線 MQTT，而是讀取由 `car.js` 服務寫入的本地 JSON 資料。

| 檔案 | 說明 |
|------|------|
| `js/data/car/car_status.json` | 最新一筆垃圾桶狀態（僅保留 1 筆） |
| `js/data/car/car_log.json` | 歷史紀錄（最多 120 筆，按時間升序） |

### 資料結構（單筆紀錄欄位）

| 欄位 | 型別 | 說明 |
|------|------|------|
| `receivedAt` | string (ISO 8601) | 伺服器接收資料的時間戳 |
| `id` | number | 最後辨識的 ID |
| `category` | string | 辨識類別代碼 (recyclable/non_recyclable/blank) |
| `category_zh` | string | 辨識類別中文名稱 |
| `target_bin` | string | 建議投放的桶別 |
| `lastUpdate` | string | 裝置運行時間（格式 `HH:MM:SS`） |
| `recyclableCount` | number | 可回收垃圾數量 |
| `nonRecyclableCount` | number | 不可回收垃圾數量 |
| `total` | number | 總數 |
| `fill_percent` | number | 桶容量佔比 (0-100) |
| `alertActive` | boolean | 是否處於滿桶警告狀態 |
| `full_bucket` | string | 滿桶位置說明 |
| `top_category` | string | 累計最多的類別 |
| `distance_cm` | number | 超音波偵測距離 (cm) |
| `object_present` | boolean | 當前是否有物體接近 |
| `ultrasonic_full` | boolean | 是否因超音波超時判斷滿桶 |
| `raw` | string | 原始 JSON payload（偵錯用） |

---

## 2. 功能說明

### 2.1 目前狀態摘要

讀取 `car_status.json`，以格式化區塊展示：
- 資料接收時間（轉換為台灣時間 UTC+8）
- 裝置運行時間
- **最後辨識類別與建議桶別**
- **可回收 / 不可回收 / 總數量 / 容量佔比**
- **超音波感測距離與物體偵測狀態**
- 系統狀態（正常 / 滿桶警告：包含滿桶位置）

### 2.2 歷史趨勢分析

讀取 `car_log.json` 最後 N 筆紀錄，輸出：
- 可回收 / 不可回收 / 總數量的平均值與最高值
- 滿桶事件次數與佔比

### 2.3 系統提醒

依照以下三條規則觸發提醒：

| 規則 | 觸發條件 | 提醒類型 |
|------|----------|----------|
| 滿桶警告 | `alertActive == true` | 🚨 紅色警告 |
| 裝置離線 | 距上次接收資料超過 30 秒 | ⚠️ 黃色警告 |
| 等待初始化 | 資料全為空值且 raw 為空字串 | ℹ️ 藍色提示 |

## 3. 使用方式

Python 腳本位於 `Script/iot_car.py`，可直接執行：

```bash
# 使用預設資料目錄（相對路徑自動定位）
python Script/iot_car.py

# 指定自訂資料目錄
python Script/iot_car.py --data-dir /path/to/js/data/car

# 指定歷史分析筆數（預設 20）
python Script/iot_car.py --log-limit 30
```

## 4. 配置參數說明

| 參數 | 預設值 | 說明 |
|------|--------|------|
| `--data-dir` | `js/data/car/` | JSON 資料目錄路徑 |
| `--log-limit` | `20` | 歷史分析的最大筆數 |
| `OFFLINE_THRESHOLD_SECONDS` | `30`（腳本內常數）| 判斷裝置離線的秒數閾值 |
